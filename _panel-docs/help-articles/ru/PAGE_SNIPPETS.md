## Сниппеты

Сниппет – это именованный кусок конфигурации Xray, который хранится один раз и подставляется в любое количество профилей по имени.

Когда профилей становится много, любое мелкое изменение превращается в рутину: например, у вас 10 профилей, и во всех одинаковый раздел роутинга. Без сниппетов правку придется повторить 10 раз. Со сниппетами вы меняете правило в одном месте, и оно автоматически подтягивается во все профили, которые на него ссылаются.

---

### Формат сниппета

Сниппет – это **всегда JSON-массив объектов**, даже если объект внутри всего один.

```json
[
  {
    "protocol": "freedom",
    "tag": "DIRECT"
  }
]
```

Требования к содержимому:

- это должен быть массив, а не объект;
- в массиве должен быть хотя бы один элемент;
- пустые объекты (`{}`) внутри массива не допускаются.

---

### Куда можно подставлять сниппеты

Сниппет подставляется в четырех местах. В трех из них это массивы, и ссылка выглядит как объект `{ "snippet": "имя" }`. В четвертом – корень конфигурации, и ссылка выглядит как массив имен.

#### outbounds\[\]

```json
{
  "outbounds": [
    {
      "snippet": "snippet-name"
    }
  ]
}
```

#### routing.rules\[\]

```json
{
  "routing": {
    "rules": [
      {
        "snippet": "snippet-name"
      }
    ]
  }
}
```

#### routing.balancers\[\]

```json
{
  "routing": {
    "balancers": [
      {
        "snippet": "snippet-name"
      }
    ]
  }
}
```

#### Корень конфигурации

В корне конфигурации ссылка задается не объектом, а массивом имен в поле `snippets`:

```json
{
  "snippets": ["log-preset", "dns-preset"],
  "inbounds": [],
  "outbounds": []
}
```

Такой сниппет должен содержать **секции корневого уровня**. Это по-прежнему массив объектов, просто ключи внутри объектов – это названия разделов конфигурации:

```json
[
  {
    "log": {
      "loglevel": "debug"
    }
  }
]
```

Секции можно как разложить по отдельным элементам массива, так и собрать в одном объекте – результат будет одинаковым:

```json
[
  {
    "log": {
      "loglevel": "debug"
    },
    "dns": {
      "servers": ["1.1.1.1"]
    }
  }
]
```

---

### Как происходит подстановка

#### В массивах

Объект со ссылкой заменяется содержимым сниппета целиком. Если в сниппете несколько элементов – на место одной ссылки встанут все они.

Было:

```json
{
  "outbounds": [{ "snippet": "my-outbounds" }]
}
```

Сниппет `my-outbounds`:

```json
[
  { "protocol": "freedom", "tag": "DIRECT" },
  { "protocol": "blackhole", "tag": "BLOCK" }
]
```

Стало:

```json
{
  "outbounds": [
    { "protocol": "freedom", "tag": "DIRECT" },
    { "protocol": "blackhole", "tag": "BLOCK" }
  ]
}
```

**Объект со ссылкой заменяется полностью.** Если рядом с `snippet` написать что-то еще, оно будет потеряно – в примере ниже `tag` не попадет в итоговую конфигурацию:

```json
{
  "snippet": "my-outbounds",
  "tag": "этот ключ будет отброшен"
}
```

Если сниппета с указанным именем не существует, элемент со ссылкой просто удаляется из массива.

#### В корне

Все перечисленные в `snippets` сниппеты собираются в один набор секций и добавляются в корень конфигурации. Само поле `snippets` из итоговой конфигурации удаляется.

При этом действуют три правила.

**Секции, уже написанные в профиле, не перезаписываются.** Если в профиле есть свой `log`, а сниппет тоже приносит `log` – останется тот, что написан в профиле. Так сделано намеренно: то, что вы написали руками, важнее того, что пришло из пресета.

**Часть секций не подставляется никогда.** Это `inbounds`, `api`, `stats`, `metrics` и `snippets` – ими управляет Remnawave, и сниппет не может их подменить. Если сниппет содержит такие секции, они молча пропускаются, а остальные его секции применяются как обычно. В редакторе сниппетов эти секции недоступны и подсвечиваются как ошибка.

**Порядок имеет значение.** Если два сниппета в списке приносят одну и ту же секцию, победит тот, что указан позже.

Если сниппета с указанным именем не существует, имя просто пропускается.

#### Порядок обработки

Сначала обрабатывается корень, затем массивы. Благодаря этому корневой сниппет может принести, например, раздел `outbounds`, внутри которого есть ссылки на другие сниппеты – они тоже будут раскрыты.

Вложенность работает **только на один уровень**: сниппет, подставленный из другого сниппета, дальше не разворачивается. Поле `snippets` внутри корневого сниппета игнорируется.
