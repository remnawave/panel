## 代码片段（Snippets）

代码片段是一段带名称的 Xray 配置，只需保存一次，就可以按名称注入到任意数量的配置文件中。

当配置文件变多时，任何细小的改动都会变成重复劳动：比如你有 10 个配置文件，它们的路由部分完全相同。没有代码片段时，同一处修改要重复 10 次。使用代码片段后，你只需在一个地方修改规则，所有引用它的配置文件都会自动获得该修改。

---

### 代码片段的格式

代码片段**始终是一个由对象组成的 JSON 数组**，即使其中只有一个对象。

```json
[
  {
    "protocol": "freedom",
    "tag": "DIRECT"
  }
]
```

内容要求：

- 必须是数组，而不是对象；
- 数组中至少要有一个元素；
- 数组内不允许出现空对象（`{}`）。

---

### 可以在哪里引用代码片段

代码片段可以在四个位置注入。其中三个位置的目标是数组，引用写成对象 `{ "snippet": "名称" }`。第四个位置的目标是配置根级，引用写成名称数组。

#### outbounds\[\]

```json
{
  "outbounds": [
    {
      "snippet": "snippet-name"
    }
  ]
}
```

#### routing.rules\[\]

```json
{
  "routing": {
    "rules": [
      {
        "snippet": "snippet-name"
      }
    ]
  }
}
```

#### routing.balancers\[\]

```json
{
  "routing": {
    "balancers": [
      {
        "snippet": "snippet-name"
      }
    ]
  }
}
```

#### 配置根级

在配置根级，引用不是通过对象定义的，而是通过 `snippets` 字段中的名称数组：

```json
{
  "snippets": ["log-preset", "dns-preset"],
  "inbounds": [],
  "outbounds": []
}
```

这类代码片段必须包含**根级配置段**。它仍然是一个由对象组成的数组，只是对象内的键是配置段的名称：

```json
[
  {
    "log": {
      "loglevel": "debug"
    }
  }
]
```

这些配置段既可以分散在数组的不同元素中，也可以集中写在一个对象里 – 结果完全相同：

```json
[
  {
    "log": {
      "loglevel": "debug"
    },
    "dns": {
      "servers": ["1.1.1.1"]
    }
  }
]
```

---

### 替换是如何进行的

#### 在数组中

含有引用的对象会被代码片段的全部内容替换。如果代码片段包含多个元素 – 它们会全部取代那一个引用。

替换前：

```json
{
  "outbounds": [{ "snippet": "my-outbounds" }]
}
```

代码片段 `my-outbounds`：

```json
[
  { "protocol": "freedom", "tag": "DIRECT" },
  { "protocol": "blackhole", "tag": "BLOCK" }
]
```

替换后：

```json
{
  "outbounds": [
    { "protocol": "freedom", "tag": "DIRECT" },
    { "protocol": "blackhole", "tag": "BLOCK" }
  ]
}
```

**含有引用的对象会被整体替换。** 如果你在 `snippet` 旁边写了其他内容，它会丢失 – 下面的例子中 `tag` 不会进入最终配置：

```json
{
  "snippet": "my-outbounds",
  "tag": "这个键会被丢弃"
}
```

如果不存在指定名称的代码片段，含有该引用的元素会直接从数组中移除。

#### 在根级

`snippets` 中列出的所有代码片段会被汇总为一组配置段，并添加到配置根级。`snippets` 字段本身会从最终配置中移除。

此处适用三条规则。

**配置文件中已经写好的配置段不会被覆盖。** 如果配置文件里已有自己的 `log`，而代码片段也带来了 `log` – 保留配置文件中的那个。这是有意为之：你亲手写下的内容比预设带来的内容更重要。

**有些配置段永远不会被注入。** 它们是 `inbounds`、`api`、`stats`、`metrics` 和 `snippets` – 这些由 Remnawave 管理，代码片段无法替换它们。如果代码片段包含这些配置段，它们会被静默跳过，而其余配置段照常应用。在代码片段编辑器中，这些配置段不可用，并会被标记为错误。

**顺序很重要。** 如果列表中的两个代码片段带来了同一个配置段，靠后列出的那个生效。

如果不存在指定名称的代码片段，该名称会被直接跳过。

#### 处理顺序

先处理根级，然后处理数组。因此，根级代码片段可以带来例如 `outbounds` 配置段，而其中又包含对其他代码片段的引用 – 这些引用同样会被展开。

嵌套**只支持一层**：从另一个代码片段中注入进来的代码片段不会被继续展开。根级代码片段内部的 `snippets` 字段会被忽略。
